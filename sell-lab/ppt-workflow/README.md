# PPT 成品包工作流

一次只做 **一套**。算力用来出草稿和多试配色，不用来铺 50 套。

当前周末优先 [../word-workflow/](../word-workflow/README.md) 的用辞包，这套 PPT 流程先挂着。

口径仍见 [../ppt.md](../ppt.md)：8–15 页、打开改字就能交差、不代写、不带品牌。

## 目录

| 路径 | 干什么 |
|---|---|
| [跑一次.md](./跑一次.md) | 丢给 agent 的任务书，按场景 slug 跑 |
| [检查清单.md](./检查清单.md) | 出稿后必须过的项 |
| `prompts/` | 大纲 / 生成 / 上架 三段提示 |
| `scenes/<slug>/spec.md` | 这一套的合同：页、配色、谁来搜 |
| `packs/<slug>/` | 产出：pptx、预览图、上架文案 |

已订的第一套场景：`weekly-report`（周报月报）。述职、答辩以后再加 `scenes/`，不要一次开三条。

## 一次怎么走

1. 确认 `scenes/<slug>/spec.md` 已写完（没有 spec 先写 spec，不要空开做）。
2. 把 [跑一次.md](./跑一次.md) 交给当前 agent，把 `<slug>` 换成例如 `weekly-report`。
3. 人过 [检查清单.md](./检查清单.md)：投影能不能看清、页是不是真用得上。
4. 预览图自己截，不要抄闲鱼同行。
5. 上架。两周 0 咨询就停，不要加套数。

## 产出约定

每个 `packs/<slug>/` 里最终要有：

- `deck.pptx` — 发给买家的源文件
- `preview/` — 封面、目录、两页内容、结尾，至少 4 张图
- `listing.md` — 标题、价格、详情、私聊回复
- `怎么改.txt` — 也可做最后一页；zip 里再放一份纯文本

不要把未过检查的 pptx 拿去上架。
