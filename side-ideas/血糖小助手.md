# 血糖控制小助手

状态：自用项目，可以记着  
不是闲鱼挂品。完整版（科普站 + 食物库 + 每餐影响）会变成要长期养的健康 App。

## 这个想法哪里好

比「再做一套万能 PPT」更像有人会反复打开的东西：

- 场景清楚：饭前想查、饭后想记
- 中式饮食（粥、粉、馒头、米饭品种、水果怎么吃）是现成 App 经常做糙的地方
- 和 `fitness-app` 同类：给自己用的执行工具，不是货架商品

如果自己或家人真的在管血糖，值得做成本地小工具。如果只是「好像能卖」，先不要做 App，顶多以后抽一张速查表。

## 主要坑

**GI 单独不够用。** 同一种米，煮成饭、粥、炒饭，GI 差一截；加了菜、肉、醋、凉了再吃，也不一样。份量要用 **GL（血糖负荷）** 才有意义：西瓜 GI 高，但平时那一牙 GL 不一定高；一大碗粥才是常见翻车。

**「这顿对血糖影响怎么样」说不准。** 个体差、服药、睡眠、走路、上一顿，都会改曲线。工具只能给 **粗分**（这顿主食偏高/中/低），不能画「预计餐后 11.2」。一说成预测，用户拿自己的试纸来对，售后和信任都会炸。

**科普有红线。** 可以写：GI/GL 是什么、为什么细粮汤粥升得快、配菜和走路能干什么。不能写：治糖尿病、停药、替代医生。页面顶上要有一句：仅供学习记录，不构成诊疗建议。

**闲鱼上同类已经很多。** 食物 GI 表、糖尿病食谱包，搜得到。你的差如果只是「又一个表」，卖不掉；差如果是「自己每天在用的记录页」，那是产品，不是 9.9 资料。

## 若要做，v1 就这些

一个能打开的本地页，数据存在浏览器里。先服务自己。

1. **速查**：常见中式主食、粥粉面、水果、奶、饮料。每条有 GI、一份大概重量、粗算 GL、一句话备注（例如「白米粥通常比米饭更顶」）。来源注明公开文献/食物表，不抄薄荷整库。
2. **记一记**：时间、哪一餐、主食是什么、大概份量、自评（稳 / 有点顶 / 明显顶）。不记账、不算卡路里、不拍照识别。
3. **几页短科普**：GI vs GL、为什么要看份量、配蛋白和纤维、饭后走走。每页一屏说完。
4. **不做**：预测曲线、用药提醒、胰岛素、个性化食谱生成、登录云同步。

界面上影响只显示三档，例如「这顿主食负担：低 / 中 / 高」，旁边写「因人而异，以自己监测为准」。

## 以后才可能拆去卖的

真的自己用顺了，可以抽出 **不说话过满** 的东西挂闲鱼，仍然按小工具/资料来，不按健康服务来：

- 常见食物 GI/GL 速查（Excel 或本地 HTML）
- 「管血糖吃饭」结构笔记（Word，不是代配餐）

在那之前不要上架，也不要和 PPT/Word 那个周末抢时间。

## 和现有项目

`fitness-app` 已经是打卡 + 云端。血糖这一套 **先不要接 Supabase**：食物表和餐记都敏感，本地足够。等自己连续记了几周，再看要不要做成仓库里一个独立目录。
