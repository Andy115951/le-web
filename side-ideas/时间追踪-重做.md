# 时间追踪：改名，不要当 Timing 的 Lite

状态：含金量方向里的软件候选，先定口径再动代码  
现有仓：`timing-lite-tauri`（产品名 Timing Lite，identifier `com.local.timinglite`）

市面上确实有同类。这不是「先换皮重做一遍」就能赢的理由，也不是「有竞品就放弃」的理由。

## 同类已经在卖什么

自动记录「当前 App / 窗口」这一层，已经有人做完了：

| 产品 | 定位 | 对你的压力 |
|---|---|---|
| Timing | Mac 原生产品，自动追踪，偏贵订阅 | 名字和玩法都是它的。现在这仓叫 Timing Lite，看起来像仿品 |
| Timemator | 同样自动抓窗口再归到项目 | 欧美买断/订阅，体验完整 |
| RescueTime / Rize | 云端 + 专注教练 | 另一条：上传、说教、月费 |
| ActivityWatch | 开源免费 | 功能够用、界面糙，免费党会去这 |
| WorkingHours 等 | 手动填工时 | 不是同一类，抢的是「导出给客户」的人 |

所以：**不要再做一个更瘦的 Timing。** 改名是必须的（也有商标味道），重做只重「给谁、解决哪一句」，采集内核可以留。

## 现有仓里真正值钱的

已经能跑，不要推倒：

- 后台采前台 App + 窗口标题
- 规则：标题/应用命中 → 项目/标签
- 本地 SQLite，正式库和开发库分开
- 菜单栏常驻、关窗不停
- 中英文界面、能打 DMG

缺的是产品一句说清，不是再写一个采集器。

## 重做时收窄成什么

一句话（给有主业、偶尔接单/做自己项目的人）：

> 不上传。规则把窗口归到「主业 / 自己的项目 / 其它」。周末打开看这周时间去哪了。买断。

不做什么：团队、同步、AI 总结一天、番茄钟、手机、和 Timing 比文档级精度。

## 多端同步 + Dashboard（像 WakaTime）？

能做，但这是另一类产品，不是 Timing Lite 加两页。

WakaTime 值钱的不是那张网页，是：

- 每个编辑器里的插件（心跳、项目、语言、文件）
- 多年积下来的兼容
- 云上的聚合、徽章、团队

你现在有的是 **Mac 前台窗口采集**，和 WakaTime 不是一层：它知道你在 Cursor 里写哪个文件；你知道 Cursor、Chatbox、浏览器各开了多久。RescueTime 才是「全 App + 云端看板」这条，而且已经有人做。

自己托管同步的话，你已经会 Vercel + Supabase，技术上拼得出来。问题是变成要养的服务：账号、冲突、账单、隐私承诺、「今天打不开了」。和主业边上买断软件不是一类。Wakapi / ActivityWatch 已经把「自建 WakaTime 后端」这条占了。

若仍想要「能在手机上看一看」：

1. 先把本地桌面端用到自己每天开
2. 导出或本机开一个只读页（还不是多端）
3. 同步做成可选项：用户自己的库，你不托管；或很晚才做官方同步

第一期不要对准 WakaTime。插件生态你一个周末铺不完，铺完还要跟编辑器升级。

差在三处，不在功能清单：

1. **中文 + 买断**（Timing 是订阅，国内很多人只是想看清自己）
2. **默认规则面向仓库/窗口**（Cursor、Chatbox、Chrome 标题、VS Code 工作区），不是通用「生产力教练」
3. **不说教**：没有「你今天专注了吗」，只有时长和未归类比例

## 名字

不要再带 Timing / Track / Time 仿品感。先记候选，未定：

- **归项**：核心就是把窗口归到项目
- **前台**：只记录前台在干什么
- **窗账**：窗口流水账

应用名、bundle id、数据目录（现在是 `~/.timing-lite`）一起换，避免装过旧版的人以为还是仿 Timing。

## 一个可收口的周末（不是重写）

1. 定名字和那句定位，改 `productName` / 窗口标题 / 数据目录
2. 默认带 4～6 条规则示例（主业、自己的仓、浏览器、即时通讯）
3. 首页只留：今日总时长、按项目、未归类、一条「去规则里收一下」
4. 时间线、英文、多余图表往后放
5. 公证/签名可以再下一轮；没签名就写明「自行允许未签名应用」

两周若自己都不想每天开，就停，不要靠「UI 再美一版」硬做。
