# Stock / NDX Event Radar 产品路线图

本文档记录 Stock 项目的完整产品目标、功能范围、数据体系、Agent 工作流、数据库演进、研发阶段和验收标准。它是“要做什么”的长期依据；本地环境、部署和排错见 [DEVELOPMENT.md](DEVELOPMENT.md)，当前代码说明见 [README.md](README.md)，现有 Supabase SQL 见 [SUPABASE_SETUP.md](SUPABASE_SETUP.md)，新人关联解读规格见 [docs/beginner-reading.md](docs/beginner-reading.md)。

## 1. 最终定位

项目长期名称暂定为 `NDX Event Radar`，中文名为“纳斯达克 100 动态日历 / 纳指市场记忆系统”。

> 一个由 Agent 驱动的纳斯达克 100 事件日历、市场记忆和情景概率分析系统。

系统主要回答：

1. 今天市场发生了什么，哪些事件可能与涨跌有关？
2. 历史上哪些环境和事件组合与今天相似，后来如何演化？
3. 当前更接近哪些未来情景，各情景的历史概率、收益和风险是什么？

输出必须使用“归因假设”“关联线索”“情景概率”等克制表达，不把相关性包装成确定因果，不承诺明日涨跌。

## 2. 项目边界

### 要做

- 以 `QQQ` / Nasdaq-100 为核心基准
- 跟踪 Nasdaq-100 成分股、权重和历史变更
- 将价格、宏观、公司公告、财报和新闻按交易时间对齐
- 自动生成每日事件卡、市场复盘和来源引用
- 建立可检索的历史事件库和相似交易日库
- 输出未来 1/3/5/20 个交易日的情景统计
- 持续记录、回测和校准历史判断
- 保留个人自选、持仓上下文、决策纪律和复盘日志
- 支持 Web/PWA 和多设备查看

### 暂不做

- 自动下单和券商账户控制
- 高频交易、盘口预测或毫秒级行情
- “明天必涨/必跌”式结论
- 没有回测依据的仓位建议
- 无来源的 AI 新闻或历史原因倒推
- 第一阶段大规模社交媒体舆情抓取
- 第一阶段桌面客户端和本地大模型

项目只用于研究、信息整理和学习，不构成投资建议。任何预测或情景输出都必须同时展示样本量、置信度、风险和数据时点。

## 3. 当前基础

当前 `stock-dashboard` 已具备：

- 原生 Web 看板
- `QQQ`、`MAGS`、美国七巨头和自选股行情
- A 股 / 美股详情接口

- Supabase Auth 和 `watchlist_states` 云同步

- 相对 `QQQ` 强弱与行动队列
- 自动个人观察记录：触发回撤纪律、目标价、相对 `QQQ` 弱势或单日显著跌幅时保留价格事实与阈值，最多 90 天并随个人账号同步
- 个人决策日志：可从观察记录一键起草，记录已做决定、理由和事后结果；跨设备 last-write-wins，不生成买卖建议
- 当日公开资讯和涨跌关联线索
- 最近事件快照及 `market_event_history` 长期归档入口
- Vercel Functions 和收盘后 Cron 骨架
- Supabase CLI 本地配置
- 新版 `SUPABASE_SECRET_KEY` 服务端访问方式
- 不依赖个人自选的 Nasdaq 核心行情/新闻雷达
- 近 36 小时新闻聚合、去重和标题相关性过滤
- 未登录可用的本地 14 天日度脉络
- 公共 `nasdaq_market_event_history` 与无登录历史 API
- 收盘 Cron 在无用户数据时仍能归档核心市场事件
- 动态日历、单日详情、NDX 成分快照与财报日历
- QQQ 五年日线、前瞻标签、日度特征、相似日和冻结 walk-forward 评估
- 研究快照、日报/周报、任务账本、确定性 Attribution / Labeler 和受控模型摘要执行器
- 生产已配置 `SEC_USER_AGENT` 与 `FRED_API_KEY`；本机已验证 filings 与宏观观测写入

公共市场数据已经落到独立的市场日、价格、事件、来源、日报和评估表；`watchlist_states` 只继续保存个人自选、持仓、观察记录和决策日志。

## 4. 目标页面

### 4.1 首页 / 今日市场

- QQQ / NDX 当日涨跌、成交量和波动状态
- Nasdaq-100 上涨/下跌家数
- 主要贡献股和主要拖累股
- 行业/主题表现
- 美债收益率、美元和重要宏观变量
- 当天高影响事件
- 新人关联解读（手动「读一下今天」）：把同屏的 QQQ、相对强弱、新闻、日历、相似日和个人纪律串成五段说明；默认不展示正文，点击才生成，行情刷新不改写。规格见 [docs/beginner-reading.md](docs/beginner-reading.md)
- AI 复盘摘要和证据来源（研究回放中的已校验模型输出，默认关闭，与上一则不是同一入口）
- 当前情景与历史相似样本摘要

### 4.2 动态日历

每个交易日展示 QQQ/NDX 涨跌、波动等级、事件数量、最高影响等级、宏观/财报/公告/指数调整标记、情景判断及后续验证结果。

支持月/周/列表视图，按事件类型、股票、行业和置信度筛选，明确区分非交易日与交易日，以美东交易日为主并标注北京时间。

### 4.3 单日详情

- 手动「读一下这一天」：与首页同一五段骨架，日期换成该市场日；切日期后正文丢弃，需再点一次
- QQQ / NDX / 主要指数表现
- 主要贡献股、拖累股和权重影响
- 宏观与公司事件时间线
- 原始来源、发布时间和市场可知时间
- 归因假设、支持证据和反例
- 历史相似日及后续 1/3/5/20 日表现
- 当时生成的情景判断
- 事后实际结果和评估

### 4.4 历史相似日

- 相似度总分
- 价格、宏观、事件、板块、波动分项相似度
- 相似依据与不相似点
- 后续收益分布、胜率、回撤和波动率

### 4.5 研究报告

- 每日收盘复盘
- 每周市场记忆摘要
- 财报季专题
- CPI / 非农 / FOMC 专题
- 单只成分股事件回放
- 某类事件历史统计报告

所有报告必须能回到来源和结构化数据，不能只保存不可解释的 AI 文本。

### 4.6 评估看板

- 历史情景数量
- 不同窗口的方向准确率
- 概率校准曲线
- 收益和最大回撤分布
- 不同市场状态和事件类型下的表现
- 模型/规则/提示词版本对比
- 失败案例与错误原因标签

## 5. 数据体系

### 5.1 价格数据

第一阶段保存 QQQ 和主要 Nasdaq-100 成分股日线 OHLCV、涨跌幅、振幅、成交量、跳空、回撤、趋势、波动率及未来 1/3/5/20 日收益标签。

后续增加 NDX 官方指数、全部成分股、调整后价格、拆股分红、行业主题篮子、个股对指数的日度贡献和盘前/盘中/盘后时段。

价格记录必须保存供应商、拉取时间、市场日期和调整方式。

### 5.2 Nasdaq-100 成分与权重

必须保存历史快照，不能用今天的成分回测过去：

- 生效日期
- 成分股和公司实体
- 权重
- 加入/移除原因
- 来源和发布时间
- 再平衡及特别再平衡事件

### 5.3 宏观数据

第一批：CPI、Core CPI、PPI、非农、失业率、FOMC、Fed 会议纪要、美国 2Y/10Y 收益率、利差和美元代理指标。

后续：零售销售、ISM、GDP、PCE、初请失业金、Fed 官员讲话和市场隐含利率概率。

每个宏观事件至少保存预期值、公布值、前值、修正值、发布时间、时区和来源。

### 5.4 公司官方事件

- SEC 10-K / 10-Q / 8-K
- Earnings Release
- 业绩指引变化
- 回购、并购、高管变动
- 重大诉讼和监管调查
- 产品发布和投资者日

公司事件关联 ticker、CIK、公司实体、事件发生时间和市场可知时间。

### 5.5 财报数据

- 计划日期、实际发布时间和盘前/盘后
- EPS / Revenue 预期、实际和 surprise
- 指引变化
- 电话会摘要和管理层关注点
- 财报后 1/3/5/20 日反应

### 5.6 市场结构事件

- Nasdaq-100 成分和权重调整
- 指数方法论变化
- 季度/年度及特别再平衡
- 大型期权到期
- ETF 资金流和重大被动资金再配置

### 5.7 新闻和舆情

公司、行业、监管、分析师和主题新闻需要去重、来源归并、保存原始 URL、首次发布时间和更新时间，并区分原始来源与转载。不能保存超出授权范围的全文。社交媒体仅作为后期弱信号。

## 6. 数据来源策略

优先级：官方 API/公告 → 交易所/指数公司 → 公司投资者关系 → 可靠数据供应商 → 新闻聚合 → 社交媒体。

来源方向：

- SEC EDGAR：filings 和 XBRL
- FRED：宏观时间序列
- 美国财政部或 FRED：国债收益率
- Nasdaq 官方：成分、方法论和调整公告
- 公司 Investor Relations：财报和公告
- 行情供应商：QQQ / NDX / 成分股 OHLCV

每个数据源接入前记录使用条款、频率限制、API Key、时间戳精度、历史覆盖、复权方式、修订机制和失败降级方案。

## 7. 统一事件模型

```json
{
  "event_id": "uuid",
  "event_time": "2026-08-07T20:05:00Z",
  "available_at": "2026-08-07T20:05:12Z",
  "market_date": "2026-08-07",
  "event_type": "earnings_guidance",
  "title": "公司更新业绩指引",
  "summary": "结构化中文摘要",
  "sentiment": "negative",
  "impact_scope": "sector",
  "impact_level": "high",
  "confidence": 0.78,
  "tickers": ["NVDA"],
  "themes": ["semiconductor", "ai_compute"],
  "source_ids": ["source-uuid"],
  "extractor_version": "event-labeler-v1",
  "created_at": "2026-08-07T20:06:00Z"
}
```

时间字段必须分开：`event_time` 是实际发生/发布时间，`available_at` 是系统或市场可获得时间，`captured_at` 是采集时间，`market_date` 是归属交易日。

## 9. Agent 工作流

### Daily Collector Agent

拉取价格、宏观、filings、财报和新闻，记录数据源与时间，负责去重、重试和降级，不负责生成最终市场原因。

### Event Labeler Agent

把原始文档转为结构化事件，识别 ticker/公司/主题/行业，标注类型、范围、方向和置信度，低置信度进入复核。

### Market Attribution Agent

对齐价格和事件，生成多个可能解释，区分市场、公司、混合和证据不足，同时给出支持证据与反例，只输出归因假设。

### Historical Similarity Agent

计算价格、宏观、事件和板块状态相似度，排除未来数据，输出分项依据和后续收益/回撤/波动分布。

### Scenario Forecast Agent

读取统计模型概率和历史样本，构建情景、触发条件、失效条件和置信度，不越权生成确定性建议。

### Reporter Agent

生成结构稳定的中文日报/周报，引用事件和来源，突出新信息、市场分歧和风险。

### Backtest / Evaluator Agent

预测到期后自动评分，检查方向、收益、回撤和概率校准，标记失败案例和数据泄漏，不自动修改生产模型。

## 10. 预测与统计原则

数字由统计模型负责：Logistic Regression 做可解释基线，Gradient Boosting/LightGBM/XGBoost 做候选，简单历史条件统计做对照，波动率模型负责风险。第一版不急于深度学习。

LLM 负责事件抽取、filing/财报摘要、归因假设、相似案例解释和报告生成；不负责凭空产生概率、替代回测、修改原始价格或在缺少来源时补写原因。

预测输出至少包含窗口、情景概率、模型置信度、样本数、收益和回撤分布、正负因素、失效条件以及模型/数据版本。

## 11. 历史相似日

相似度由价格状态、波动状态、市场广度、宏观状态、事件组合和板块状态组成。

要求：

- 显示分项相似度，不只给单一向量分数
- 明确样本不足
- 连续日期避免重复占满结果
- 未来收益严格从匹配日之后开始
- 标准化参数只使用当时以前的数据拟合

## 12. 回测与评估

目标包括未来 1/3/5/20 日方向、收益、最大回撤和波动率。

指标包括 Accuracy、Balanced Accuracy、Precision/Recall、Brier Score、Log Loss、概率校准、平均/中位收益、最大回撤、概率分桶实际胜率，并与永远上涨、简单动量等基线比较。

必须使用 walk-forward：按时间滚动训练验证，只使用当时可知信息，保存宏观首次公布值，使用历史真实成分，测试集不反向参与规则调优。

## 13. 技术架构方向

当前：原生 Web + Vercel Functions + Supabase + Vercel Cron + Node.js。

中期：Web/PWA 为主，结构化数据在 Supabase，Python Worker 负责回填、特征和回测；Vercel 承载前端和轻量 API，重任务迁到 Worker 服务，原始文档按授权需求使用 Storage。

只有出现本地模型、离线研究、大量本地文件、本地数据库或交易终端联动需求后才考虑 Tauri 桌面端。

## 15. 可观测性与运维

每个任务保存 run_id、类型、开始/结束时间、数据日期、输入数、成功/失败数、重试数、数据源状态、代码版本和错误摘要。

需要建设 Cron 日志、失败告警、数据缺失/接口变化告警、单日补抓、日期范围回填、幂等重跑和任务看板。

## 16. 安全与隐私

- Secret Key 仅服务端使用
- Publishable Key 可在浏览器使用，但用户表必须启用 RLS
- Cron 使用独立 Secret
- Access Token 不进入聊天、文档、日志和仓库
- 错误日志不打印密钥、完整上游响应和隐私数据
- 持仓、成本和决策日志属于私有用户数据
- 公共数据和用户数据分表分权
- 泄露时立即撤销、轮换并检查访问日志

## 17. 关键数据风险

- 幸存者偏差：回测必须使用历史成分和权重
- 未来函数：收盘后信息不能解释或预测当天盘中
- 时间戳错误：发布、可知、采集和反应时间分开
- LLM 过度归因：允许 `unclear`，展示反例和证据不足
- 宏观修订：保留首次公布值和修订版本
- 公司行为：处理拆股、分红、代码变化和并购
- 样本过少：显示样本量，防止过拟合
- 数据授权：确认许可和再分发限制
